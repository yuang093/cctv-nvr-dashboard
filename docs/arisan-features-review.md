# Arisan Gateway 功能吸收評估清單

**目的**：從 `Arisan-Gateway-使用手冊.pdf` 抽出「值得加入 8444 系統」的功能，列成清單供檢查。
**產出時機**：修改計畫藍圖前的 review 階段。
**撰寫日期**：2026-07-17

---

## 約束條件（user 已明示）

1. **目標系統**：8444（背景 worker v1 + Web UI v2）
2. **NVR 連線不能改**：Avigilon REST API（port 8443）+ Media API（fmp4）— 既有 `AvigilonScanner`、`MediaApiClient` 契約不變
3. **架構不能改**：v1 worker 寫 DB，v2 Web UI 唯讀；加新功能不能倒過來
4. **新功能可以加**：dashboard / events / 影像分析 / 報告這些 UI 與 DB 派生邏輯可以加

## 建議納入的下階段清單（用 ★ 數量排序）

### ⭐⭐⭐ 強烈建議：影像健康巡檢（PDF 第 6 章重點功能）
**為什麼**：Arisan 把這列為「影像健康巡檢」是賣點之一；8444 目前只看連線狀態，不看影像本身是否真的有錄到東西。
**粗略規劃**：
- 在 worker 抓 jpeg 縮圖（clip 同樣 API）
- 寫簡單規則：mean pixel（亮）、std（對比）、frame diff（凍結偵測）
- 結果寫新表 `image_health_checks`（cam_id / checked_at / blur / occluded / overexposed / frozen / shifted）
- 每 N 分鐘跑一次（背景排程）

### ⭐⭐ 強烈建議：相機牆（PDF 第 3 章）
**為什麼**：操作員一眼就看到「哪些紅、哪些灰」，比表格掃視更直覺。
**粗略規劃**：
- Dashboard 上加 `/wall` 路由：grid × N 張縮圖
- 縮圖用 Media API 的 jpeg（clips app 已有經驗）
- 異常用卡片取代：訊號中斷紅卡、無訊號琥珀卡
- NVR 異常時這台 NVR 下屬全相機一併灰卡

### ⭐⭐ 強烈建議：探索網段（PDF 第 5 章）
**為什麼**：新 NVR 上線時不必逐台手動輸入。
**粗略規劃**：
- web route `POST /nvrs/discover` 帶網段 `192.168.0.0/24`
- 用 `AvigilonScanner` 嘗試登入每個 IP（timeout 短）
- 結果頁列出哪些 IP 回應了 Avigilon API，可批次加入

### ⭐ 建議：處理狀態徽章強化 + 「此相機正常」基準線學習
**為什麼**：目前 4 狀態已對齊 PDF；「此相機正常」（學基準）可以讓重複誤報自動消失。
**粗略規劃**：
- `cameras.baseline_json` 欄位：學到的「這台正常的影像指標」
- events 表加 `is_baseline` 旗標或獨立 `baseline_rules` 表

### ⭐ 建議：Dashboard 磁磚點擊跳已篩選檢視
**為什麼**：超低成本高 UX 改善。
**粗略規劃**：
- `/?tile=signal_lost` 等 query 參數
- `/events?status=pending&kind=signal_lost`

### ⚪ 可選：Chart.js 健康圖表、單台詳情頁、品牌分佈
**為什麼**：nice-to-have
**粗略規劃**：放後面迭代

### ❌ 不加：雲端、授權、AI 模型下載、Fleet Pulse、SNMP/交換器

## 與既有契約的關係（變更警告）

| 變更類型 | 影響 | 處理 |
|---|---|---|
| DB schema 新增 `image_health_checks` 表 | 新表，不影響既有 | OK |
| DB schema 新增 `cameras.baseline_json` | 加欄位；migration 加 ALTER TABLE | 需小心不破壞既有資料 |
| `AvigilonScanner` 介面 | 新增 `probe_image_health()` 方法 | 可加，不破壞既有 method |
| `MediaApiClient` 介面 | 不變（jpeg 抓取用既有 `fetch_thumbnail`） | OK |
| Web UI 路由 | 加 `/wall`、`/devices/discover`、dashboard 磁磚化 | OK（8444 已有多路由） |
